# Объяснение проекта и подготовка к защите

## Идея проекта

Divide and conquer означает «разделяй и властвуй»: большую задачу делим на подзадачи, решаем их и получаем общий результат. В проекте сравниваются четыре применения этой идеи. Два алгоритма сортируют массив, один выбирает элемент заданного ранга, ещё один ищет ближайшие точки на плоскости.

`Main.java` показывает примеры. `Experiment.java` запускает измерения. `Metrics.java` хранит счётчики одного запуска. `DataSets.java` создаёт воспроизводимые входные данные. `Point.java` описывает точку. Каждый алгоритм находится в отдельном классе.

## MergeSort простыми словами

Делим массив пополам, сортируем обе половины, затем объединяем их. При объединении сравниваем первые ещё не использованные элементы половин и переносим меньший. Поэтому объединение занимает линейное время.

Массив `auxiliary` создаётся один раз, а не заново на каждом уровне. Маленькие части длиной не больше 24 сортируются вставками: для них простые циклы часто дешевле дополнительных рекурсивных вызовов.

Пример: `[4, 1, 3, 2]` превращается в две отсортированные части `[1, 4]` и `[2, 3]`; слияние даёт `[1, 2, 3, 4]`. В самой программе такой короткий пример целиком попадёт под cutoff и будет обработан вставками.

Рекуррентность: `T(n) = 2T(n/2) + Θ(n)`. В Master Theorem: `a=2`, `b=2`, `f(n)=Θ(n)`, второй случай. Результат: `Θ(n log n)`. Память: `O(n)` под буфер и `O(log n)` под стек.

## QuickSort простыми словами

Выбираем случайный pivot - опорное значение. Разбиваем данные на три части: меньше pivot, равно pivot, больше pivot. Средняя часть уже стоит правильно. Остальные две нужно отсортировать.

Три указателя поддерживают границы областей. Когда элемент больше pivot, он меняется с элементом справа; текущий индекс сразу не увеличивается, потому что пришедший справа элемент ещё не проверен.

Главная особенность: вызываем рекурсию только для меньшей части. Большую продолжаем обрабатывать циклом. Поэтому каждый новый уровень стека получает не больше половины текущей задачи. Стек ограничен `O(log n)` даже при неудачных pivot. Но суммарная работа всё ещё может быть `O(n²)`.

Среднее ожидаемое время: `Θ(n log n)`. Худшее: `Θ(n²)`. На полностью одинаковом массиве трёхстороннее разбиение заканчивает работу за `Θ(n)`.

## Deterministic Select простыми словами

Нужно найти элемент, который оказался бы на позиции `k` после сортировки. Полностью сортировать массив не требуется. Например, для `[9, 1, 7, 3, 5]` и `k=2` ответ 5, потому что отсортированный массив равен `[1, 3, 5, 7, 9]`.

Индекс считается с нуля. `k=0` - минимум, `k=n-1` - максимум. В измерениях берётся `k=n/2`; при чётном `n` это верхняя из двух центральных позиций.

Шаги алгоритма:

1. Разделить данные на группы по пять.
2. Отсортировать каждую маленькую группу и взять её медиану.
3. Собрать медианы в начале того же массива.
4. Рекурсивно найти медиану этих медиан.
5. Использовать её как pivot и разбить исходный диапазон на три части.
6. Перейти только в часть с позицией `k`, либо вернуть pivot, если `k` попал в равную область.

Почему это линейно? Каждая подходящая полная группа гарантирует три элемента по одну сторону pivot. С обеих сторон можно гарантировать примерно `3n/10` элементов с учётом постоянной поправки. Значит оставшаяся часть не больше `7n/10 + O(1)`.

Верхняя оценка: `T(n) <= T(n/5) + T(7n/10) + O(n)` с округлением размеров. Сумма долей 0,2+0,7=0,9 меньше единицы, и суммарная работа по уровням ограничена геометрическим рядом. Получаем `O(n)`; вместе с нижней оценкой - `Θ(n)`. Обычная Master Theorem напрямую не подходит: размеры подзадач разные. В README показано объяснение через Akra-Bazzi. Дополнительная память - `O(log n)` для стека.

## Closest Pair простыми словами

Нужно найти две точки с минимальным евклидовым расстоянием. Полный перебор проверяет каждую пару и делает `n(n-1)/2` вычислений.

Быстрый алгоритм сортирует точки по x, делит их на две части и находит ближайшую пару в каждой. Обозначим лучший результат через `delta`. Более близкая пара, пересекающая границу, должна находиться в полосе шириной `2*delta` вокруг неё.

В полосе точки рассматриваются по y. Для каждой достаточно проверить не более семи следующих точек: больше полезных соседей не помещается в соответствующей области при известной минимальной дистанции внутри половин. Проверка останавливается ещё раньше, если разность y уже не меньше лучшего расстояния.

Порядок по y получается линейным слиянием результатов дочерних вызовов. Если сортировать полосы заново на каждом уровне, время станет `O(n log² n)`. В нашей реализации: `T(n)=2T(n/2)+O(n)`, то есть `O(n log n)`; память `O(n)`.

## Как были получены результаты

Размеры: 100, 1 000, 10 000, 100 000 и 300 000. Типы: случайные, отсортированные, обратные и с большим числом повторов. Перед измерением есть прогрев JVM. Для каждого случая записано семь запусков; в таблице времени используется медиана, а для глубины - максимум этих запусков.

`System.nanoTime()` вызывается перед алгоритмом и после него. Разность даёт время. Генерация данных и эталонные проверки находятся снаружи измеряемого участка. Внутренние буферы алгоритмов и счётчики входят в измерение.

Seed фиксирует последовательность псевдослучайных чисел: вход и pivot можно воспроизвести. Время не будет побитово повторяться, потому что на него влияют JVM и операционная система.

## Частые вопросы и короткие ответы

**1. Почему нужен вспомогательный массив в MergeSort?** Чтобы безопасно сливать половины, не затирая ещё не использованные элементы. Один буфер переиспользуется на всех уровнях.

**2. Что означает stable sort?** Равные по ключу элементы сохраняют исходный относительный порядок. MergeSort в проекте стабилен; QuickSort не гарантирует стабильность.

**3. Случайный pivot гарантирует O(n log n)?** В ожидании, но не для каждого запуска. Худший случай остаётся O(n²).

**4. Почему маленький стек не означает быстрое выполнение?** Глубина учитывает одновременно активные вызовы; большой объём работы может выполняться последовательными итерациями цикла.

**5. Зачем три части в partition?** Равные pivot элементы сразу исключаются из дальнейшей обработки; это помогает при повторениях и гарантирует прогресс.

**6. Почему именно группы по пять?** Их медианы легко найти за постоянное время, и они дают нужную гарантию отбросить постоянную долю элементов. В стандартном анализе групп по три сумма долей не даёт такого же линейного доказательства.

**7. Почему Select не сортирует весь массив?** Ему нужна одна позиция. После разбиения достаточно продолжить поиск только с нужной стороны.

**8. Где используется Akra-Bazzi?** Для неравных подзадач n/5 и 7n/10 у median of medians. Уравнение для p: (1/5)^p + (7/10)^p = 1, причём 0<p<1; линейная нерекурсивная работа даёт итог O(n).

**9. Что происходит с пустым массивом?** Сортировки ничего не делают. Select отклоняет запрос, потому что допустимого k нет. Closest Pair возвращает отсутствие пары и бесконечную дистанцию.

**10. Что происходит при совпадающих точках?** Минимальное расстояние равно нулю; одинаковые координаты допустимы.

**11. Как проверялась корректность?** Сортировки и выбор элемента сравнивались с Arrays.sort, ближайшая пара - с полным перебором для маленьких наборов. Есть отдельный большой пример с заранее известной дистанцией.

**12. Почему нельзя запускать полный перебор на всех больших наборах?** Число пар растёт квадратично. Для 300 000 точек это 44 999 850 000 пар, поэтому для большого эксперимента используется быстрый алгоритм.

**13. Почему время не растёт идеально по формуле?** Формула описывает асимптотику. На секунды влияют константы, кэш, JIT, выделение памяти, GC и другие процессы.

**14. Зачем нужны CSV и несколько повторов?** CSV сохраняет исходные данные для проверки и повторного построения графиков. Несколько повторов позволяют оценить разброс; медиана меньше зависит от одного медленного запуска.

**15. Какие улучшения возможны?** Отдельные процессы JVM для повторов, JMH для более строгих замеров, подбор cutoff и сравнение версий со счётчиками и без них. Эти улучшения не заявлены как уже выполненные.
